# アプリケーション要件：`sea-movie-creator`
AIチャットから動画編集の操作を行える、軽量な動画編集ソフトです。

## 1. 画面構成（1ウィンドウ）
操作感は「AviUtl」に近く、画面の雰囲気は「DaVinci Resolve」や「VS Code」、チャット欄の見た目は「VS Code」に近づけます。
- **上部**：メニューバー
- **右側（初期幅は画面の1/5）**：タブ切り替えパネル（AIチャット画面、選択中の部品の設定画面などを切り替え可能）
- **中央部**：動画のプレビュー再生画面
- **下部**：タイムライン編集画面

## 2. 最低限の必須機能
- 動画を読み込み、滑らかに再生できること。

## 3. 各モジュールの仕様
- **メイン画面**：動画再生、各モジュールへのアクセス、AIチャット機能を持つ土台。
- **動画書き出しモジュール**：
  - ソフトの専用フォルダにファイルを追加するだけで機能が増える「プラグイン形式」にする。
  - 1つの書き出し形式（例：H264）につき1つのモジュールとする（H265を出力したい場合は別モジュールを追加する形）。
  - ソフトウェア処理・ハードウェア処理（GPU支援）の両方の書き出しに対応する。
- **動画編集モジュール**：
  - タイムライン上の動画に対し、大きさ変更、位置変更、回転、透明度、色調整、拡大率（縦横）を編集できる。
  - 時間経過による変化（直線変化など、再生すると徐々に拡大する動き）を設定できる。AIが扱いやすい `f(t)=...` のような数式形式をベースにしつつ、人間が画面のつまみ等で微調整できる設計にしてください。
  - AIチャットと人間の手動操作の両方から編集できる。
- **字幕モジュール**：
  - キャンバス上に文字を配置できる。
  - 動画編集モジュールと同様の変形・色調整・時間変化・AIと手動の両操作に対応する。
- **音楽モジュール**：
  - 動画に音声やBGMを流せる。音量変更、再生速度変更ができる（理想はVST2、VST3の外部音声プラグインに対応すること）。
  - AIと手動の両操作に対応する。
- **画像モジュール**：
  - キャンバス上に画像を配置できる。
  - 動画編集モジュールと同様の変形・色調整・時間変化・AIと手動の両操作に対応する。

## 4. タイムラインの仕様
- AviUtlのように、どの段（レイヤー）にも動画・字幕・音楽・画像を自由に配置できる。
- 段の数はメモリが許す限り無制限（技術的に難しい場合は上限64）。
- カット編集、ドラッグ＆ドロップでの移動、コピー、ペースト、複製ができる。
- **カット編集時の挙動**：分割した後半のパーツは「元の動画や音楽の途中」から再生され、時間変化（アニメーション）も「変化の途中」から始まること。前半のパーツは変化の途中までで終わること。

## 5. 技術方針と制約
- **技術構成**：軽量化のため「Rust + GPUI」を採用したい。動画再生はGPUとCPUの両方を活用し、CPUだけに頼って重くならない仕組みを設計してください。
- **AviUtl拡張機能の取り込み**：公開されているAviUtlの拡張機能をそのまま読み込めるか検討し、技術的に難しければ見送ってください。その場合は「ゆっくり実況者向けの専用モジュール（音声合成や立ち絵連携など）」を別途作る計画にしてください。

# テストの配置ルール（instructionsに必ず反映すること）
- **単体テスト**：各部品の `.rs` ファイル内の最後にテストコードを記述する。
- **結合テスト・全体テスト**：`tests/<実装名>/` フォルダ内に記述する。
  ※Rustの仕組み上、`tests/<実装名>/` フォルダ内のテストが自動で認識されるよう、入り口となる `tests/<実装名>.rs` もあわせて配置するルールにしてください。
